# Testing

## Current state
**No automated test suite has been written for this project, and none has been run.** Testing is deliberately deferred until implementation work is finished (owner's standing rule). The Laravel + web pass is done; the Android app and browser add-ons are not, so the suite is still pending.

What exists in `laravel/tests/` was generated by the Breeze starter kit, not written for this project:
`tests/Feature/Auth/*` (registration, authentication, password reset/update/confirmation, email verification), `tests/Feature/ProfileTest.php`, `tests/Feature/ExampleTest.php`, `tests/Unit/ExampleTest.php`, `tests/TestCase.php`.

**These have never been executed here.** Their status is *Not run* — not passing, not failing. PHPUnit 12.5 is installed as a dev dependency; Pest is not installed. (fiyobra uses Pest + Playwright, which would be the natural choice when a real suite is written.)

## Manual verification actually performed
This is what was run against the built app, and what it demonstrated. None of it is an automated test.

| Area | Method | Result |
| --- | --- | --- |
| Migrations | `php artisan migrate:fresh --seed` | All 11 migrations apply cleanly against MySQL 8.0; no FK errors |
| Routes | `php artisan route:list` | 32 web module routes, 37 `api/v1` routes registered with expected middleware |
| Frontend build | `npm run build` | Vite compiles all module pages with no errors |
| Format / lint | `vendor/bin/pint`, `npm run lint` | Both clean |
| Models | `php artisan tinker` script | UUIDv7 keys generated; enum + datetime casts work; `user_id` correctly rejected as non-fillable; balance math 50000 − 12550 = 37450 cents |
| Page loads (authenticated) | HTTP session walk of all 10 module pages | All 200 with Inertia payloads |
| Web CRUD | HTTP form posts per module | Note, preset, snippet, workout, history entry and budget account all created and visible in their lists |
| Workout due-state | HTTP, before/after logging | `dueForReminder` true before logging, false after — correct hourly logic |
| Budget arithmetic | HTTP: deposit R500, withdraw R125.50, transfer R100 | Cash 27450c (R274.50), Savings 10000c (R100.00) — exact |
| Overdraft rejection | HTTP: withdraw R9999 from a R500 account | Rejected; balance unaffected |
| Same-account transfer | HTTP: transfer Cash → Cash | Rejected |
| Transfer integrity | SQL audit of `transfer_group_id` | Every transfer group has exactly 2 legs |
| **Cross-tenant isolation (web)** | Second user attacking 9 of the first user's routes by real UUID | All 9 return **404**; victim's data intact; attacker's lists empty |
| **Cross-tenant isolation (API)** | Second token attacking 5 of the first user's endpoints | All 5 return **404**; attacker's index listings empty |
| **Cross-owner writes** | SQL audit joining transactions to account owners | **0** rows where poster ≠ owner — the scoped `Rule::exists` holds |
| API token lifecycle | HTTP | No token → 401; wrong password → 422; correct → 201; revoke → 204; revoked token → 401 |
| History prune | `php artisan history:prune` against seeded data | Deleted exactly the 1 row older than 90 days, left 5 newer rows; `--days=0` rejected |
| Scheduler | `php artisan schedule:list` | `history:prune` registered daily (`0 0 * * *`) |

Caveat on method: the first run of the isolation check silently passed for the wrong reason (a scripting bug meant record ids never parsed, so every request hit a nonexistent id and 404'd trivially). It was re-run with real UUIDs and an abort-guard before being believed. A written suite should encode that guard.

What manual checking did **not** cover: real browser interaction (clicks, the Pomodoro countdown advancing, `navigator.clipboard` copy, dark mode, responsive layouts), concurrency on transfers, and anything on Android or in a browser extension.

## When the suite is written
Scope it to the six modules (PRD.md F-01…F-06) plus the SECURITY.md requirements, with these layers:
- **Unit**: `BudgetService` (deposit/withdraw/transfer/delete-both-legs, insufficient funds), `WorkoutReminderStatus::isDue` around hour boundaries, `formatZar`.
- **Integration/Feature**: per-module CRUD through both the web and `api/v1` surfaces; FormRequest validation rules; token issuance and revocation.
- **Tenant isolation**: the highest-value tests. Worth copying fiyobra's `tests/Feature/Security/CrossTenantAccessTest.php` approach — a data-driven sweep over every model-bound route asserting 404 for a non-owner, **plus** its self-auditing test that walks the live route table and fails the build when a new bound route is added without a corresponding isolation case.
- **E2E**: Playwright for the real browser behavior listed as uncovered above.
